### F32B-PSBT-Q-001 — D-02: PSBT_GLOBAL_XPUB policy

Factual context: the parent draft leaves the global-xpub map policy open. The global map may in principle carry zero or more PSBT_GLOBAL_XPUB entries, and the trusted descriptor D fixes exactly three account xpubs (A, B, C).

RECOMMENDED CANDIDATE — UNSELECTED: the global map allows zero to three PSBT_GLOBAL_XPUB entries, any subset of the exact A/B/C account xpubs already fixed in trusted D. Absence of every PSBT_GLOBAL_XPUB entry is valid and supports no identity inference. Each keydata is the raw 78-byte BIP32 serialization, not Base58 text, and must be exactly equal to one D account xpub in every field: mainnet public version bytes, depth, parent fingerprint, child number, chain code, and compressed public key. The value must exactly match the corresponding master fingerprint plus the path m/48h/0h/0h/2h: four little-endian path elements, with depth, path count, and full byte consumption all checked. Matching is always the full xpub-plus-origin-plus-role comparison, never fingerprint alone. Any foreign, extra, alternate-depth, wrong-network, wrong-origin, malformed, duplicate, or ambiguous entry rejects the whole PSBT. A matching global-xpub entry never substitutes for trusted D, wallet_id, per-input or per-output derivations, ownership proof, or factor agreement, and grants no authority.

Alternatives and tradeoffs: reject all PSBT_GLOBAL_XPUB entries (simplest, but discards a benign interoperability aid); require all three entries whenever any is present (stricter and unnecessary, since absence is already valid). The candidate trades a small privacy surface (repeating known account xpubs inside the PSBT) for coordinator interoperability; no alternative changes trust, because D is only the trusted local comparison baseline for metadata consistency, and signing authority still requires the authorized factor ceremony and physical approval.

### F32B-PSBT-Q-003 — D-06: change and self-transfer classification

Factual context: the parent draft leaves open how outputs claiming to be wallet-derived are classified.

RECOMMENDED CANDIDATE — UNSELECTED: an exhaustive review labels every output exactly one of PROVEN D CHANGE-BRANCH SCRIPT; PROVEN D RECEIVE-BRANCH SELF-TRANSFER SCRIPT; NOT PROVEN D-DERIVED — TREATED AS RECIPIENT. Proof requires the complete A/B/C trio of output BIP32 derivations: each full public key, origin, and path must match its D role; all three must share one common coordinate m/48h/0h/0h/2h/{0,1}/index; branch and index elements are unhardened; the index respects the still-open common QK-LIM index ceiling; the three keys are distinct; the core sorts the keys and constructs the exact sortedmulti(2,A,B,C) witnessScript; and the transaction output is the exact native P2WSH scriptPubKey for it. Branch 1 is change; branch 0 is a separate self-transfer class. PSBT_OUT_WITNESS_SCRIPT is unnecessary. If present, it is accepted only with a complete D-derived candidate and must byte-match the independently derived witnessScript; otherwise the PSBT rejects. PSBT_GLOBAL_XPUB is likewise unnecessary for this proof. Missing, coherent-but-incomplete, or unrelated structurally valid output BIP32-derivation metadata yields class 3. A malformed or contradictory D-linked proof, multiple distinct coordinates, a duplicate role, extra derivations on an otherwise proven D output, a witnessScript mismatch, or a complete tuple whose script does not match rejects the whole PSBT. External labels are ignored; they can neither create ownership nor alone cause rejection. The proof establishes only descriptor derivability and script match — not key possession, spendability, freshness, intent, chain state, or non-reuse.
